# Claude Code work order — app icon and manifest

Artwork: `assets/` in the design export. Artboard: `App Icon.dc.html`.

## Files to wire

| File | Size | Purpose |
|---|---|---|
| `icon-192.png` | 192×192 | `any` |
| `icon-512.png` | 512×512 | `any` |
| `icon-maskable-192.png` | 192×192 | `maskable` |
| `icon-maskable-512.png` | 512×512 | `maskable` |
| `apple-touch-icon.png` | 180×180 | iOS home screen |
| `favicon-32.png` | 32×32 | browser tab |

All six come from one 32×32 master upscaled nearest-neighbour: 512 is ×16, 192 is ×6,
favicon is ×1. 180 is composed rather than scaled — the master at ×5 (160px) centred on a
180px ink ground with 10px of bleed. **Never resample these files.** If another size is
ever needed, it must be an integer multiple of 32 or composed the same way; a 128 or a 256
generated by scaling 512 will blur the pixel art.

## manifest.webmanifest

```json
{
  "name": "Times Table",
  "short_name": "Times Table",
  "description": "Multiplication and division practice.",
  "start_url": "./index.html",
  "display": "standalone",
  "orientation": "portrait",
  "background_color": "#f3eee1",
  "theme_color": "#f3eee1",
  "icons": [
    { "src": "./assets/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "./assets/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "./assets/icon-maskable-192.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
    { "src": "./assets/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

Keep `any` and `maskable` as separate entries, not `"purpose": "any maskable"` — the two
files differ (the maskable gem is smaller so it clears the 80% safe circle), and collapsing
them would ship the wrong one for one of the two cases.

## index.html head

```html
<link rel="icon" href="./assets/favicon-32.png" sizes="32x32" type="image/png">
<link rel="apple-touch-icon" href="./assets/apple-touch-icon.png">
<meta name="theme-color" content="#f3eee1">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="default">
```

The existing `theme-color` meta already says `#f3eee1` — the manifest was the one that
disagreed. `status-bar-style: default` because a light theme colour needs dark status-bar
content; Android infers this, iOS does not.

## The two rulings, and why

**`background_color: #f3eee1`.** This is the splash ground while the installed app boots,
and the first painted screen is parchment. Any other value is a flash of the wrong colour
on every cold start. The stale `#fbfaff` predates the design system.

**`theme_color: #f3eee1`.** The manifest's `#6b4de6` predates the system and contradicts
the head. Parchment wins because it is what the screen under the chrome actually is — the
status bar should disappear into Home rather than sit on it as a band. It also keeps the
promise the system makes everywhere else: **the app has no purple in it.**

## Standing rules

- **The icon never themes.** My Look repaints five decorative surfaces inside the app; the
  icon is not one of them. It is the app's face on a home screen shared with other apps,
  and a face that changes when she picks Nether is a different app twice a month.
- **No radius is drawn into the artwork.** The OS owns the corner; a baked-in one shows as
  a double edge under a circle mask.
- **The ground is opaque to all four edges** in every variant, so iOS never fills
  transparency with black and no mask shape can expose a corner.
